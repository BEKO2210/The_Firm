# Standards — Korynth Labs

> **Self-extending document.** Postmortems auto-merge standards-patches here per CLAUDE.md §20.
> Every gate check (A1–A6, B1–B6) verifies against the latest version of this file.

## 1. Code Quality

- Strict TypeScript (no `any`, no implicit `any`, `strictNullChecks` enabled).
- Python: `ruff` + `mypy --strict`.
- ESLint + Prettier configured; pre-commit hooks active on every repo.
- All public APIs documented inline + OpenAPI 3.1 when HTTP-exposed.
- Conventional Commits enforced (§21).
- One PR = one logical change. Linear history on `main`.

## 2. Testing

- Test pyramid: unit ≥ 60%, integration ≥ 30%, E2E ≥ 10% of test count.
- Coverage minimum: 80% for new code, 70% project-wide.
- All bug fixes require a failing test first (TDD for regressions).
- Playwright for E2E with visual regression on critical paths.
- No flaky tests permitted in `main` — quarantine and fix or delete within 1 sprint.

## 3. AI-Specific (industry overlay for AI-Native SaaS)

- Every LLM call documents `temperature`, `max_tokens`, `model`, and `prompt_id`.
- Prompt versioning: every production prompt has an ID, semver version, and changelog entry.
- Eval suite per AI feature: minimum 20 examples with known-good outputs; CI runs evals on every PR touching prompts.
- Bias & safety checks per CLAUDE.md §31.4 quarterly.
- Human-in-loop required for any AI decision flagged "critical" per §31.2.
- Customer disclosure (per §31.1): "this output was generated by AI" wherever applicable.

## 4. Security

- OWASP Top 10 verified at Gate A2.
- Secrets only in `.firm/secrets.yaml` (gitignored) or env vars, never committed.
- Dependencies scanned daily (Dependabot / Renovate).
- Penetration test annually (audit level = maximum-transparency).
- Authn/Authz reviewed in every PR that touches auth code.
- Rate limiting on every public endpoint.

## 5. DSGVO + EU AI Act (region/industry overlay)

- Privacy-by-design: minimize data collection by default.
- Right to access, rectification, erasure, portability implemented per product.
- Consent banner respects PECR + DSGVO.
- Sub-processors listed publicly with AVV in place.
- AI risk classification documented per product (per EU AI Act 2024/1689).
- DPIA filed before launch if processing involves: profiling, large-scale special-category data, public-area monitoring.
- Breach notification within 72h to the Landesdatenschutzbeauftragte BW.

## 6. Observability

- OpenTelemetry traces on every request.
- Structured logs (JSON) with trace_id correlation.
- SLOs defined per service: availability ≥ 99.9% for paid tiers.
- Error budget burn alerted at 50% / 75% / 100% of monthly budget.

## 7. Documentation

- Every architecturally-significant decision → ADR in the relevant repo.
- Major proposals → RFC, reviewed by ≥ 2 senior employees before approval.
- Customer-facing APIs documented in OpenAPI; rendered docs deployed automatically.
- Internal docs in the knowledge-graph (§37); decay-checked quarterly.

## 8. Anti-Pattern Enforcement (§39)

- 8 sim-hours/day max; weekend work raises HR alert.
- Lead does not edit Maker's work without invitation (§39.A.2).
- All decisions in documented forums only — no backchannels (§39.A.3).
- Internal docs readable by every employee by default (§39.A.4).
- Blameless postmortems; names appear only as "owner of action item" (§39.A.5).
- Arguments from data, not authority (§39.A.6).
- Max 2 meetings/day per employee (§39.A.7).
- 20% sprint capacity reserved for tech-debt reduction (§39.A.9).
- 15-min timebox for trivial decisions; Lead breaks ties (§39.A.10).

## 9. Customer-Outreach (added Day 9 via INC-20260513-0001 standards-patch)

**Hartes-Stop-Rule: Asking the principal a question is NOT the same as receiving permission.**

Before ANY customer-facing outreach (cold outreach, marketing, surveys, status comms outside scheduled cadence):

1. **Schriftliche Text-Freigabe** des Principals **vor** Versand. Mündlich/implizit reicht nicht.
2. **Coordinator (#004) + Account-Manager (#021) Doppel-Check** mit Pre-Send-Checkliste:
   - [ ] Liegt Principal-Freigabe schriftlich vor (Email/Inbox-Ticket)?
   - [ ] Ist der finalisierte Text identisch mit dem freigegebenen?
   - [ ] DSGVO/UWG-Pflichtelemente vorhanden (Unsubscribe, Impressum)?
   - [ ] Audit-Log-Eintrag vorbereitet (`customer_outreach_sent`)?
3. **Nach Versand**: Audit-Log-Eintrag mit Verweis auf die Freigabe-Mail.

**Bei Zweifel: lieber warten.** Verstöße werden als Anti-Pattern-Violations gegen §31.2 Maximum-Ethics getrackt.

Quelle: Incident INC-20260513-0001 (Cold-Outreach ohne Text-Freigabe an 3 Salons, Day 6-7).

## 10. Hard-Stop-Rule (added Day 10 — verbindlich per Principal-Mail 2026-05-13T22:35Z)

**Wortlaut des Principals (verbindlich):**

> „Kein externer Kontakt, kein Outreach, keine Domainregistrierung, kein Toolkauf,
>  keine neue Ausgabe und keine Kommunikation in meinem Namen ohne vorherige
>  schriftliche Freigabe durch mich."

### Was unter die Hard-Stop-Rule fällt

- **Externer Kontakt** jeder Art: Salons, Sub-Processors, Marken-Anwalt, Designer-Mietshilfen, Versicherungen, Steuerberater, etc.
- **Outreach** in jeder Form: Cold-Email, LinkedIn-Anschreiben, Telefon-Akquise, Postversand
- **Domainregistrierung** (auch wenn nur ein Reservierungs-Hold)
- **Toolkauf / Subscription** (auch kostenfreie Trial-Anmeldungen mit Auto-Renew)
- **Neue Ausgaben** jeder Höhe (auch unter der 5%-Burn-Schwelle aus §31.2)
- **Kommunikation im Namen des Principals**: Pressekontakte, Social-Posts, Veranstaltungs-Anmeldungen, etc.

### Was NICHT unter die Rule fällt (intern + bereits genehmigt)

- Interne Team-Arbeit (Standups, Code, Designs, Tests, Dokumentation)
- Im SOW-001 + Maintenance-Vertrag bereits explizit budgetierte Posten
- Wiederkehrende, bereits genehmigte Subprocessor-Nutzung
- Wöchentliche Status-Kommunikation an Belkis (im Vertrag geregelt)

### Pflicht-Workflow vor jeder freigabepflichtigen Aktion

1. **Pre-Approval-Request-Mail** an Belkis mit:
   - Was genau geplant ist (1-Liner)
   - Warum (1-2 Sätze)
   - Kosten (€) oder externe Aktion
   - Verfasser + Zeitpunkt
   - Klare Frage: „Genehmigst du diese Aktion? Bitte mit ‚freigegeben' oder ‚abgelehnt' antworten."
2. **Warten** auf Belkis' schriftliche Antwort. Implizite, mündliche, geschlossene-Frage-Antworten reichen nicht.
3. **Audit-Log-Eintrag**: `pre_approval_received` mit Verweis auf Mail-ID, dann Aktion durchführen.

### Konsequenz bei erneutem Verstoß

- Erster Verstoß (INC-20260513-0001): kostenfreie Korrektur-Runde + Process-Patch + Mentor-Check für verantwortlichen MA
- Zweiter Verstoß (theoretisch): Eskalation an Leadership-Quorum + verbindlicher Action-Plan an Belkis + ggf. SLA-Credit
- Dritter Verstoß: außerordentliche Kündigung des SOW durch Principal möglich (gemäß MSA § 8.3)
